## Causal boundary and the +7.48/+7.49 rounding boundary

The failures are **not explained by the xte destination-year/source-year convention**: the third run also changed numerically fitted *cod and Edwards* core results that do not call the xte sensitivity script. Its cod JSON has 232 changed floating leaves (maximum absolute difference 2.22×10⁻⁵), Edwards JSON 81 (maximum 4.89×10⁻¹²); the cod seeded-bootstrap changes propagate from the fitted parameters. This is arithmetic/optimizer cross-environment sensitivity, not a timestamp or JSON-key-order difference. The exact machine-level cause (BLAS build, optimizer stopping path, CPU arithmetic, etc.) is **not isolated**; strict core byte reproducibility remains intermittent. The xte SciPy optimizer's K varied by about 1.2 kt across hosted/local environments and is separately stabilized by the analytic interior least-squares solution; this does not silently fix the core scripts.

For xte, both candidate scripts use the same source-year residual definition and the same model/data and parameter box. The original one-line candidate takes the SciPy numerical fit `r=0.5022786802321234`, `K=4812.875015889598`; the analytic interior least-squares solution has `r=0.5022616936162659`, `K=4813.06428484024`. The five historical changed core files all pass this report-only comparator, as do identical files. Injecting a changed fitted parameter, a sub-absolute-limit but relative-limit violation, a missing JSON key, a changed nested interval value and a changed CSV header each fails; log: `numeric_policy_report_only_tests.log`. An out-of-envelope future run must fail and preserve both files. This tested policy, **not** a silent whitelist, is being promoted to the hosted verifier.
