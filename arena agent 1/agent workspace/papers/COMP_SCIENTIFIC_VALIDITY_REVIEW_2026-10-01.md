### A. `prop:redesign`'s “exact delay threshold” and viable equality are **false as stated**

Upstream lines 1107–1145 (live v16 same block) dilate the *post-revelation* actuator to `aU` and assert `τ_max(a)=7/50+(a−1)/2`, **“equality viable”**, explicitly plotting `a=2, τ=16/25`. These values fit the paper's fixed horizon `T=6/5`, and the original three branches and shared blind-window control remain within the model's assumptions. This is not a Lean claim.

Let `λ=(3/8,5/16,5/16)` and the paper's unit normals `n₁,n₂,n₃`. Exactly `Σλ_j n_j=0`. For **every** measurable shared control before revelation, the weighted normal position at time `t≤τ` is `34/25+t` and weighted normal velocity is `1`. At the claimed viable endpoint `τ=16/25`, weighted position is **2**, the positional safety ceiling. If every branch is safe there, all three (positive-weight) critical positions equal 2, and at least one has strictly outward velocity. Bounded post controls cannot avert its immediate exit. Stronger, choose legitimate stored labels at `t=τ+1/10=37/50<T`: even granting each branch independent control in `2U` afterward, `n_j·u_j≥−2` gives the weighted critical position lower bound `34/25+37/50−2(1/10)²/2=209/100>2`. This is an **explicit finite three-label obstruction of margin `9/100` at the claimed viable endpoint**, so it is not just failure to exhibit a viable policy.

The written proof has independent sign/representation errors: `max_{u∈aU}⟨u,n_j⟩=−a` is impossible (`u=a n_j∈aU` yields `+a`); the relevant minimum is `−a`. If `U={u:Fu≤f}`, writing `F_a=aF, f_a=af` describes **the same U**, not `aU` (which uses `Fu≤af`). The figure/script tests the zero of *one selected dual expression* `Γ_a(τ)`, not the true optimized viability threshold. Its original endpoint label `t=τ+1` also leaves the fixed horizon when `τ>1/5`, so that witness cannot establish the advertised larger rungs as written. **Classification:** false manuscript threshold/equality, outside Lean; the affine formula may describe that particular witness on its valid domain, not an exact viability law. Retain the audited `a=1` facts unless separately refuted.

### B. `prop:beliefcells` needs load-bearing cell-label/error hypotheses; clause (ii) is false as written

Upstream lines 980–1015 (live same) replace a stored margin by `β_a^C=sup_{(θ,x)∈C}β_a(θ,x)+δ_C`, then claim the value sandwich **“verbatim”** and that splitting a cell erodes a witness by **exactly** the control-kernel expression (12). But when `β` is remaining facet margin, the **worst** state has the *smallest* `β`; a supremum plus a radius is an optimistic label suitable for a one-sided lower-bound relaxation, not an exact robust label. A cell's diameter/label discrepancy must be charged separately before claiming an upper sandwich.

A one-mode linear example stays inside the baseline initial-safety/compact-polytope assumptions: `ẋ=1`, `U={0}`, `D={0}`, `P=C=[0,1/2]`, safety `0≤x≤1`, `T=1`. The true robust violation value is `J=1/2`. For the upper facet at `t=1`, `β_x=1−x−1=−x`, so `β_robust=−1/2`. Taking the **exact** cell centered at `1/4` with position radius `δ_C=1/4`, the displayed `sup+δ_C` yields `β^C=+1/4` — a gap **3/4**, not 1/4. The resulting no-control LP has `ρ=−1/4`; charging only `δ_C` and a fine grid's small `L h_t` cannot upper-bound `J=1/2`. To recover an upper bound under the original bridge's (H6), a separately verified `δ_β≥3/4` would have to be included; `δ_C` alone does **not** satisfy that hypothesis. Thus the counterexample is to the extension's unqualified “verbatim”/radius reading, **not** to `thm:bridge` with its full (H6). Because the optimistic cell label relaxes constraints, a *positive* cell LP value can still be a sound obstruction under the appropriate one-sided row ordering; the example does not refute that narrower soundness direction.

Independently, clause (ii)'s **exact** formula cannot ignore changing labels: with `ẋ=0`, the same cell `C=[0,1/2]` and upper facet `x≤1` has `k=0` so the (12) kernel erosion is **zero**, yet `sup_C β_x+δ_C=5/4` while the singleton cell `{x=1/2}` has label `1/2`; its contribution changes by `3/4`. That violates an “exactly (12)” claim without invoking any approximation limit. A corrected general identity must include label/enclosure changes and specify how observation-conditioned controls are represented. The proposition's primal-witness radius claim (iii) also needs to distinguish an **actual held-policy safety slack** from slack in the relaxed LP rows; the latter alone does not certify viability.

### C. Proof prose overstates moment/radius inequalities, without refuting the main bridge

Supplementary Step 2, lines 91–104, invokes `|A_av−∫k_a^⊤u|≤\bar e_a` for `\bar e_a≥e_a=∫h_U(\bar k_a−k_a)`. This is **false for an asymmetric two-dimensional actuator polytope**. On one block take `U=conv{0,e₁,e₂}` and equal-third kernel values `k=e₁,e₂,−e₁−e₂`, so `\bar k=0`. The displayed one-sided `e` is `1/3`; the reverse deviation can be `2/3` (take `u=e₁,e₂,0` on the thirds). This can be embedded under (H1)–(H6): use a scalar linear plant `ẋ=B(t)u` with `B(t)` taking those three row values, an exact singleton initial state, no disturbance, and a closed halfspace safety constraint. Bounded piecewise-constant `B` gives uniform time Lipschitzness, BV kernels and `L¹` time-label continuity; the one-block control mesh, compact triangular `U`, and exact initial/disturbance data supply the remaining hypotheses. The **required one-sided inequality (3) remains true**, and the upper sandwich uses held controls, whose moment discrepancy is zero; this is a *proof assertion to remove/narrow*, not a demonstrated counterexample to the main bridge. The uniform centered radius/TV bound can control both orientations if separately invoked.

Main theorem explanation around upstream line 449 says pointwise `h_U(g)≤R_U‖g‖` when `R_U` is a radius about *some fixed center*. For `U={100}` centered at 100, `R_U=0` but `h_U(1)=100`. The **integrated** moment-error estimate can still be valid: subtract the center first, since `∫_J(\bar k−k)=0`. Supplementary Step 1 uses this cancellation correctly. This is another invalid shortcut in prose, not an obstruction to the centered integral estimate.
